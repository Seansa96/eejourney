Tags: [[Test Driven Development]]

Test Driven Development refers to the practice of building tests, referred to as [[Unit Tests]], first, then the actual functions and methods of the program as fully realized applications of those unit tests.

Essentially, you write the automated unit tests, *then* make those tests work and produce the desired result, then you actually implement then in your main project.

This is particularly effective in large scale projects where compile time can make testing individual logical components cumbersome or in web applications where it can be costly or time intensive to test logic modules.

It is less effective, to sometimes detrimental in small scale projects where it is often simply more efficient to "build and see", but it still serves as a viable development tool.

Test Driven Development is particularly effective as a way of self-documentation, providing clear demonstrations of what the logic is supposed to achieve.
